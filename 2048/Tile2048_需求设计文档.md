# Tile2048 - 2048 小游戏 Codelab 需求设计文档

## 一、项目概述

### 1.1 项目名称

- 英文标识：Tile2048
- 中文名称：2048 小游戏

### 1.2 项目背景

OpenHarmony Codelabs 仓库包含了丰富的 UI 组件、Ability、数据、媒体类 demo，但 **没有任何图形交互类游戏**。现有最接近的游戏类是 MathDash（文字答题），属于 Q&A 模式而非图形交互。Tile2048 将填补这一空白，展示 Canvas 绘制、手势识别、动画控制和游戏逻辑的完整开发流程。

### 1.3 项目定位

Tile2048 是一款基于 OpenHarmony（API 12+）的**经典 2048 滑动拼数游戏**，在 4×4 网格中通过滑动合并相同数字，最终合成 2048 即获胜。提供顺滑的方块移动动画、分数记录和最高分持久化，帮助开发者掌握触摸手势识别和 Canvas 游戏渲染的核心技术。

### 1.4 目标用户

| 用户 | 说明 |
|------|------|
| OpenHarmony 初学者 | 学习 Canvas 游戏开发和手势识别的入门实战 |
| 游戏开发者 | 参考 2048 核心算法和动画实现 |
| 普通玩家 | 在开发板上休闲娱乐 |

### 3.2 核心用例描述

#### UC-01：一局游戏流程

| 项目 | 内容 |
|-----|------|
| **前置条件** | 用户打开应用，看到 4×4 棋盘，初始有 2 个随机方块 |
| **主流程** | 1. 棋盘初始状态：随机位置出现 2 个方块（值 2 或 4）<br>2. 用户手指在棋盘区滑动（上/下/左/右）<br>3. 系统识别滑动方向<br>4. 该方向上的方块滑动到最远端，相同数字合并<br>5. 合并后生成新方块（2 或 4）在随机空位<br>6. 分数累加（合并的两个数字之和）<br>7. 重复 2~6 步<br>8. 当棋盘满且无可合并方块 → 游戏结束<br>9. 显示结算弹窗 |
| **异常流** | E1：滑动方向无变化（方块无法移动）→ 不生成新方块，棋盘不变<br>E2：游戏进行中误触返回 → 保持当前状态 |
| **后置条件** | 游戏结束，分数计入最高分比较 |

#### UC-02：方块合并规则

```
滑动前 (向左滑动):         滑动后:
┌──┬──┬──┬──┐            ┌──┬──┬──┬──┐
│2 │  │2 │  │            │4 │  │  │  │
├──┼──┼──┼──┤            ├──┼──┼──┼──┤
│4 │4 │8 │  │            │8 │8 │  │  │
├──┼──┼──┼──┤    →       ├──┼──┼──┼──┤
│  │  │  │  │            │  │  │  │  │
├──┼──┼──┼──┤            ├──┼──┼──┼──┤
│  │  │  │  │            │  │  │  │  │
└──┴──┴──┴──┘            └──┴──┴──┴──┘
规则：
1. 每行数字按滑动方向靠拢
2. 相邻相同数字合并（每次滑动每行最多合并一次，从远端开始算）
3. 合并后靠拢端对齐
4. 一次滑动中，一个方块只参与一次合并
```

### 4.3 核心算法：GameEngine

```
GameEngine 核心数据结构:
  grid: number[][]     // 4×4 二维数组，0 表示空位
  score: number        // 当前分数
```

### 7.2 存储

最高分使用 `@ohos.data.preferences` 持久化：

```typescript
const PREF_KEY = 'tile2048_pref'
const BEST_SCORE_KEY = 'best_score'

class ScoreManager {
  async getBestScore(context: Context): Promise<number> {
    const prefs = await context.getPreferences(PREF_KEY)
    return prefs.get(BEST_SCORE_KEY, 0)
  }

  async saveBestScore(context: Context, score: number): Promise<void> {
    const prefs = await context.getPreferences(PREF_KEY)
    const current = await this.getBestScore(context)
    if (score > current) {
      await prefs.put(BEST_SCORE_KEY, score)
      await prefs.flush()
    }
  }
}
```

## 九、关键难点与解决方案

| 难点 | 描述 | 解决方案 |
|------|------|---------|
| 滑动算法正确性 | 2048 的合并规则容易出错（一次滑动的合并顺序） | 用"去零→合并→补零"三步法，先过滤零再相邻合并 |
| 手势误触 | 轻点也被识别为滑动 | 设置最小滑动距离阈值（30px），不足时不触发 |
| Canvas 自适应 | 棋盘需要适配不同屏幕尺寸 | 使用 `aspectRatio(1)` 让棋盘为正方形，动态计算 tileSize |
| 颜色方案 | 方块背景和文字颜色需要区分度高 | 预置颜色映射表，2~2048 各自独立配色 |
